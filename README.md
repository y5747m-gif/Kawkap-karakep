# كوكب كراكيب

منصة عربية RTL وMobile First لبيع الكراكيب والمواد القابلة لإعادة الاستخدام **بإشراف مالك الموقع**. العميل يرسل طلب بيع، يراجعه المالك، ثم يُسنده إلى تاجر موثوق ومناسب للتخصص والمنطقة. لا تبدأ أي عملية بيع أو محادثة تشغيلية قبل هذه المراجعة.

## ما تم بناؤه

- **رحلة بيع محكومة:** إرسال طلب بيع → مراجعة المالك → إسناد إلى تاجر → دردشة مرتبطة بالإسناد → تقييم التاجر.
- **دليل تجار موثوقين:** تخصص، مدينة، حالة اعتماد، تقييم وعدد مراجعات لكل تاجر.
- **دردشة العميل والتاجر:** واجهة محادثة توضح أن التواصل يُستخدم بعد توجيه المالك للطلب، مع عرض تقييم التاجر داخل المحادثة.
- **متجر مصغّر للتاجر:** بوابة دخول للتاجر تعرض الطلبات المُسندة إليه، وتتيح له إضافة عرض شراء لكل طلب وتعديله، بالإضافة إلى إدارة قائمة أسعار متجره الخاصة.
- **طلب عميل مكتمل:** نموذج طلب البيع يطلب اسم العميل ورقم الهاتف والصنف والكمية والوصف والمنطقة والعنوان التفصيلي والوقت المناسب؛ لا يراها إلا مالك الموقع والتاجر المُسند إليه الطلب.
- **كل طلب يتجه إلى واتساب المالك:** عند إنهاء أي طلب بيع تُجهَّز رسالة مرتبة تشمل رقم الطلب والهاتف والنوع والكمية والموقع والعنوان والوقت والحالة، ثم يفتح واتساب مباشرة على رقم المالك `01013178718`. تظهر أيضًا خطوة أخيرة كبيرة وواضحة لإعادة فتح الرسالة إذا حجب المتصفح النافذة.
- **واجهة سهلة قليلة القراءة:** الرئيسية مختصرة إلى «صوّر، اختار، ابعت»، ونموذج البيع مقسّم إلى ٣ خطوات مصوّرة بأزرار كبيرة بدل الحقول الطويلة، مع اختيار النوع والكمية والحالة والمحافظة بالنقر.
- **مساعدة لغير القادرين على الكتابة:** قراءة صوتية عربية لكل خطوة، وإملاء صوتي للاسم والمنطقة والعنوان والملاحظات، وزر لتحديد الموقع الحالي من الهاتف، ورقم الهاتف هو الحقل الوحيد المطلوب كتابته في الخطوة الأخيرة.
- **مساعدة واتساب دائمة:** زر ظاهر في الشريط العلوي وعلى سطح المكتب، ورابط «مساعدة» ثابت في شريط الهاتف، وكلها تتجه إلى `01013178718` برسالة مساعدة جاهزة.
- **إشعارات نشطة:** إشعارات داخل المنصة لكل الأطراف عند طلب جديد أو موافقة أو إسناد أو عرض سعر أو تقييم، مع طلب إذن إشعارات الجهاز من المتصفح.
- **تثبيت كتطبيق:** زر علوي لتثبيت الموقع كتطبيق PWA من المتصفح على الهاتف. لا ينتج ملف APK أصليًا، لكنه يثبت ويعمل كتطبيق مستقل عند دعم المتصفح.
- **حسابات حقيقية بدورين:** التسجيل ينشئ حسابًا فعليًا (الاسم، رقم الهاتف، كلمة مرور مُجزَّأة) محفوظًا في المتصفح، مع تحقق كامل من المدخلات ورسائل خطأ عربية واضحة، وإمكانية تسجيل الدخول لاحقًا من `/login`.
  - العميل: يحدّث عداد العملاء فقط؛ لا يظهر الاسم أو بيانات الهوية في الواجهة أو سجل التجار.
  - التاجر: يرسل طلب اعتماد ويظهر في سجل التجار الخاص بالمالك بحالة «بانتظار الاعتماد»، مع رقم تواصله ونبذته للمالك فقط.
- **لوحة مالك مبسطة:** لا يوجد تسجيل عام للمالك؛ الدخول من بوابة خاصة، ثم تظهر الطلبات في بطاقات واضحة تحتوي اسم العميل ووسيلة التواصل والعنوان والوصف، مع اختيار التاجر والاعتماد بضغطة واحدة.
- **خصوصية العملاء:** بطاقة إحصاء وعدّاد فقط؛ لا تُعرض بيانات العملاء في دليل عام أو لوحة التجار.
- **شعار محدّث وهوية موحّدة:** يظهر الشعار الجديد في الشريط العلوي والصفحة الرئيسية والتذييل وصورة المشاركة الاجتماعية، مع ألوان متسقة في الوضعين الفاتح والداكن.
- **واجهة أبسط للاستخدام:** تنقّل رئيسي مباشر، زر بيع بارز، مسار مرئي للطلب، مداخل سريعة لأهم المهام، شريط تنقّل سفلي مناسب للهاتف، وتذييل منظم للروابط المهمة.

> بيانات الواجهة الحالية تجريبية وتُحفظ محليًا في `localStorage` لتجربة التدفقات من دون خادم. امسح بيانات الموقع من المتصفح لإعادة بيانات العرض الافتراضية.
>
> رابط `wa.me` يفتح محادثة المالك ويملأ الرسالة، لكن واتساب يشترط أن يضغط المستخدم زر الإرسال بنفسه. الإرسال الآلي بلا هذه الضغطة يحتاج WhatsApp Business Cloud API وخادمًا آمنًا؛ لذلك توضح شاشة النجاح هذه الخطوة بصريًا ولا تدّعي أن الرسالة أُرسلت قبل تنفيذها.

## الضبط الأمني والنشر (جديد)

هذه النسخة (1.1.0) مرّت بمراجعة أمنية وجودة شاملة قبل النشر:

- **تجزئة كلمات مرور حقيقية:** SHA-256 بملح عشوائي لكل حساب (بادئة `k2$`) بدل التجزئة السابقة، مع دعم التحقق من الحسابات القديمة. كلمة المرور لا تُحفظ نصًا صريحًا أبدًا.
- **خفض محاولات الاختراق:** بعد ٥ محاولات دخول خاطئة لنفس الرقم أو لبوابة المالك، يُقفل الدخول ٥ دقائق مع رسالة عربية واضحة.
- **رؤوس أمنية على Vercel:** CSP صارم، `X-Frame-Options: DENY`، `X-Content-Type-Options`، `Referrer-Policy`، `Permissions-Policy`، `HSTS`، وسياسات كاش صحيحة للأصول المُجزَّأة و`sw.js` (انظر `vercel.json`).
- **PWA كاملة الأركان:** أيقونات PNG بأحجام 192/512 عادية وmaskable وأيقونة Apple، صورة مشاركة `og-cover.png` بمقاس 1200×630، واختصارات تطبيق في `manifest.json`.
- **SEO ومشاركة اجتماعية:** Open Graph وTwitter Cards كاملة، بيانات منظمة JSON-LD (WebSite + Organization + SearchAction)، sitemap شامل لكل الصفحات العامة، وrobots يستثني الصفحات الخاصة.
- **متانة الواجهة:** ErrorBoundary يمنع الشاشة البيضاء، صفحة 404 حقيقية، عنوان صفحة لكل مسار، إرجاع التمرير لأعلى عند التنقل، وترحيل بيانات النسخة (`kawkap_data_version`) يمنع تعطل الواجهة بسبب أشكال بيانات قديمة.
- **إتاحة (A11y):** رابط تجاوز للمحتوى، `:focus-visible` واضح، احترام `prefers-reduced-motion`، حوارات باسم `role="dialog"` تُغلق بزر Escape، نصوص بديلة للصور، وتباين ألوان مطابق لـ WCAG AA.
- **أداء:** تحميل الخطوط بـ preconnect بدل `@import` الحاجب، صور `loading="lazy"` مع `decoding="async"`، وأصول بناء بكاش دائم.
- **تحقق من المدخلات في كل النماذج:** أطوال قصوى، نطاقات أسعار وكميات، تحقق هاتف مصري، فحص نوع وحجم الصور قبل الإرسال، وحماية تكرار التقييم من نفس الجهاز.
- **جودة الكود:** ESLint 10 مضبوط ويمر نظيفًا (`npm run lint`)، وإصدارات معتمادات مقفلة بدل `latest`.

## التشغيل

```bash
npm install
cp .env.example .env.local
npm run dev
```

ثم افتح `http://localhost:5173`. للإنتاج:

```bash
npm run lint     # فحص جودة الكود (يجب أن يمر نظيفًا)
npm run build    # بناء الإنتاج في dist/
npm run preview  # معاينة نسخة الإنتاج محليًا
```

## مسارات الواجهة

| المسار | الغرض |
| --- | --- |
| `/sell` | إرسال طلب بيع جديد للمراجعة |
| `/orders` | متابعة حالات طلبات البيع |
| `/traders` | دليل التجار وتقييمهم |
| `/chat` | محادثة العميل والتاجر بعد الإسناد |
| `/market?q=` | فرص البيع المعتمدة مع بحث عبر الرابط |
| `/trader-login` أو `/trader` | دخول التاجر ومتجره المصغّر وأسعاره وعروض الشراء |
| `/login` | تسجيل دخول العميل أو التاجر برقم الهاتف وكلمة المرور |
| `/notifications` | إشعارات الدور الحالي وطلب إذن إشعارات الجهاز |
| `/register` | تسجيل خارجي كعميل أو تاجر |
| `/owner-login` | بوابة مالك الموقع ولوحة الإسناد |
| أي مسار آخر | صفحة 404 عربية مع روابط عودة |

### الدخول والتسجيل

| الدور | طريقة الدخول |
| --- | --- |
| عميل / تاجر | `/register` لإنشاء حساب، ثم `/login` بالرقم وكلمة المرور |
| تاجر تجريبي | الأرقام `01000000001` حتى `01000000005` وكلمة المرور `Trader@2026` |
| مالك الموقع | `/owner-login` ببيانات `VITE_OWNER_USERNAME` / `VITE_OWNER_PASSWORD` (الافتراضي `owner` / `Kawkap@2026`) |

تُحفظ الحسابات في `localStorage` ضمن المفتاح `kawkap_accounts`، وتُخزَّن كلمات المرور بعد تجزئتها بـ SHA-256 وملح محليًا فقط.
**لا تعتمد هذا الأسلوب في الإنتاج:** يجب أن تتم المصادقة والتحقق من الصلاحيات على الخادم (Supabase Auth أو Edge Function).

> كل وصول إلى `localStorage` و`sessionStorage` يمر عبر `src/auth.js` بطبقة آمنة مع بديل في الذاكرة، حتى لا تتعطل الواجهة أو يفشل الدخول عند تعطيل تخزين المتصفح (التصفح الخاص، الإطارات المضمّنة، حجب تخزين الطرف الثالث). بعد ٥ محاولات دخول خاطئة يُقفل الدخول مؤقتًا ٥ دقائق (خفض محاولات الاختراق) مع دعم التحقق من حسابات النسخة القديمة.

## البنية

- `src/main.jsx`: الواجهات، التنقل، تدفقات التسجيل، الإسناد والدردشة التفاعلية، ErrorBoundary، عناوين الصفحات، وصفحة 404.
- `src/auth.js`: طبقة تخزين آمنة، تطبيع أرقام الهواتف، تجزئة SHA-256 بملح، خفض محاولات الدخول، ترحيل بيانات النسخة، وإدارة الحسابات وبيانات المالك.
- `src/data.js`: بيانات العرض للتجار وفرص البيع والتصنيفات.
- `src/styles.css`: نظام التصميم المتجاوب والوضع الداكن مع قواعد الإتاحة.
- `src/ux-refresh.css`: طبقة تحسين تجربة الاستخدام والهوية الجديدة للشريط العلوي والرئيسية والتذييل والتنقل على الهاتف.
- `supabase/schema.sql`: مخطط Supabase وسياسات RLS لخصوصية العملاء وقرار الإسناد المركزي.
- `public/logo.svg`: شعار المنصة المحدّث.
- `public/icons/`: أيقونات PWA (عادية + maskable + Apple) بأحجام متعددة.
- `public/og-cover.png`: صورة المشاركة الاجتماعية 1200×630.
- `public/sw.js`: عامل الخدمة — شبكة أولًا مع بديل أوفلاين وكاش للأصول.
- `public/theme-init.js`: يضبط الوضع الداكن قبل أول رسم لمنع وميض الثيم.
- `vercel.json`: rewrite للـ SPA + رؤوس الأمان وسياسات الكاش.
- `eslint.config.js`: قواعد فحص جودة الكود.

## Supabase والإنتاج

1. أنشئ مشروع Supabase وشغّل `supabase/schema.sql` في SQL Editor لمشروع جديد.
2. فعّل Email أو Phone في Authentication، وأضف رابط الموقع إلى Redirect URLs.
3. أنشئ bucket خاصًا لصور طلبات البيع وسياسات رفع تتيح للعميل رفع صور طلبه فقط.
4. نفّذ عمليات حساسة عبر **Edge Functions** أو خادم موثوق: اعتماد تاجر، إضافة تاجر يدويًا، إسناد طلب إلى تاجر، إنشاء المحادثة، حفظ عرض الشراء، وتحديث متوسط التقييم.
5. أنشئ إشعارات داخلية في جدول `notifications` لكل طرف معني، واحفظ Web Push subscription بعد أن يمنح المستخدم الإذن. إرسال Web Push نفسه يجب أن يكون من Edge Function وليس المتصفح.
6. استخدم الدالة `client_registration_count()` للعداد العام فقط، واستخدم `sale_opportunities` للفرص المعتمدة بدل قراءة جدول `sale_requests` مباشرة.
7. لا تضع service-role key أو منطق اختيار التاجر أو صلاحية `admin` في الواجهة.

## النشر على Vercel

اربط المستودع، اختر Vite، واضبط Build Command على `npm run build` وOutput على `dist`. أضف متغيرات البيئة في Vercel، وسجّل نطاق الإنتاج في Supabase Auth. يحتوي `vercel.json` على rewrite من `/(.*)` إلى `/index.html` لتعمل روابط SPA المباشرة دون خطأ 404، مع رؤوس الأمان وسياسات الكاش.

### قائمة فحص ما قبل النشر

- [ ] `npm run lint` يمر نظيفًا و`npm run build` ينجح بلا أخطاء.
- [x] رؤوس الأمان (CSP وHSTS وغيرها) مضبوطة في `vercel.json`.
- [x] أيقونات PWA وصورة المشاركة وsitemap وrobots موجودة في `public/`.
- [ ] **غيّر بيانات مالك الموقع الافتراضية**: اضبط `VITE_OWNER_USERNAME` و`VITE_OWNER_PASSWORD` في Vercel قبل أول نشر حقيقي (تظهر لوحة المالك تحذيرًا أصفر طوال استخدامها). الأفضل: انقل مصادقة المالك إلى Supabase Auth.
- [ ] سجّل نطاق الإنتاج في Google Search Console وأرسل `sitemap.xml`.
- [ ] اختبر التثبيت كتطبيق (PWA) على أندرويد وiOS ورابط مشاركة واحد على كل من واتساب وفيسبوك لتظهر صورة `og-cover.png`.
- [ ] عند الانتقال لبيانات حقيقية: اربط Supabase ونفّذ الخطوات أعلاه، ولا تعتمد على `localStorage` لأي بيانات فعلية.
