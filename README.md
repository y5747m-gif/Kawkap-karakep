# كوكب كراكيب

منصة عربية RTL وMobile First لبيع الكراكيب والمواد القابلة لإعادة الاستخدام **بإشراف مالك الموقع**. العميل يرسل طلب بيع، يراجعه المالك، ثم يُسنده إلى تاجر موثوق ومناسب للتخصص والمنطقة. لا تبدأ أي عملية بيع أو محادثة تشغيلية قبل هذه المراجعة.

## ما تم بناؤه

- **رحلة بيع محكومة:** إرسال طلب بيع → مراجعة المالك → إسناد إلى تاجر → دردشة مرتبطة بالإسناد → تقييم التاجر.
- **دليل تجار موثوقين:** تخصص، مدينة، حالة اعتماد، تقييم وعدد مراجعات لكل تاجر.
- **دردشة العميل والتاجر:** واجهة محادثة توضح أن التواصل يُستخدم بعد توجيه المالك للطلب، مع عرض تقييم التاجر داخل المحادثة.
- **تسجيل خارجي بدورين:**
  - العميل: يحدّث عداد العملاء فقط؛ لا يظهر الاسم أو بيانات الهوية في الواجهة أو سجل التجار.
  - التاجر: يرسل طلب اعتماد ويظهر في سجل التجار الخاص بالمالك بحالة «بانتظار الاعتماد».
- **لوحة مالك الموقع:** تتيح اعتماد التجار، إيقافهم، إضافة تاجر يدويًا من مساحة المالك فقط، ومراجعة كل طلب ثم اختيار التاجر الذي يستلمه.
- **خصوصية العملاء:** بطاقة إحصاء وعدّاد فقط؛ لا تُعرض بيانات العملاء في دليل عام أو لوحة التجار.
- **شعار محدّث** وهوية بصرية موحدة للمنصة.

> بيانات الواجهة الحالية تجريبية وتُحفظ محليًا في `localStorage` لتجربة التدفقات من دون خادم. امسح بيانات الموقع من المتصفح لإعادة بيانات العرض الافتراضية.

## التشغيل

```bash
npm install
cp .env.example .env.local
npm run dev
```

ثم افتح `http://localhost:5173`. للإنتاج:

```bash
npm run build
```

## مسارات الواجهة

| المسار | الغرض |
| --- | --- |
| `/sell` | إرسال طلب بيع جديد للمراجعة |
| `/orders` | متابعة حالات طلبات البيع |
| `/traders` | دليل التجار وتقييمهم |
| `/chat` | محادثة العميل والتاجر بعد الإسناد |
| `/register` | تسجيل خارجي كعميل أو تاجر |
| `/owner-login` | بوابة مالك الموقع ولوحة الإسناد |

تستخدم تجربة لوحة المالك بيانات دخول محلية فقط: `owner` / `Kawkap@2026`. **لا تستخدم هذا الأسلوب في الإنتاج.**

## البنية

- `src/main.jsx`: الواجهات، التنقل، تدفقات التسجيل، الإسناد والدردشة التفاعلية.
- `src/data.js`: بيانات العرض للتجار وفرص البيع والتصنيفات.
- `src/styles.css`: نظام التصميم المتجاوب والوضع الداكن.
- `supabase/schema.sql`: مخطط Supabase وسياسات RLS لخصوصية العملاء وقرار الإسناد المركزي.
- `public/logo.svg`: شعار المنصة المحدّث.

## Supabase والإنتاج

1. أنشئ مشروع Supabase وشغّل `supabase/schema.sql` في SQL Editor لمشروع جديد.
2. فعّل Email أو Phone في Authentication، وأضف رابط الموقع إلى Redirect URLs.
3. أنشئ bucket خاصًا لصور طلبات البيع وسياسات رفع تتيح للعميل رفع صور طلبه فقط.
4. نفّذ عمليات حساسة عبر **Edge Functions** أو خادم موثوق: اعتماد تاجر، إضافة تاجر يدويًا، إسناد طلب إلى تاجر، إنشاء المحادثة، وتحديث متوسط التقييم.
5. استخدم الدالة `client_registration_count()` للعداد العام فقط، واستخدم `sale_opportunities` للفرص المعتمدة بدل قراءة جدول `sale_requests` مباشرة.
6. لا تضع service-role key أو منطق اختيار التاجر أو صلاحية `admin` في الواجهة.

## النشر على Vercel

اربط المستودع، اختر Vite، واضبط Build Command على `npm run build` وOutput على `dist`. أضف متغيرات البيئة في Vercel، وسجّل نطاق الإنتاج في Supabase Auth. يحتوي `vercel.json` على rewrite من `/(.*)` إلى `/index.html` لتعمل روابط SPA المباشرة دون خطأ 404.
